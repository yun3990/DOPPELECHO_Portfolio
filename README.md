# ImposterGame — 코드 발췌

Unity + [Mirror](https://github.com/MirrorNetworking/Mirror) 기반 **비대칭 멀티플레이어 1인칭 협동·추리 게임**입니다.
정거장에 고립된 승무원들이 탈출 미션을 수행하는 동안, 정체를 숨긴 임포스터가 이를 방해합니다.

> **이 저장소는 전체 프로젝트가 아니라 핵심 스크립트 13개를 골라낸 발췌본입니다.**
> 다른 파일에 대한 참조가 남아 있어 그대로 컴파일되지 않습니다. 읽기용으로 만들었습니다.

## 무엇을 보면 되는가

네 가지 주제로 골랐습니다. 각 주제는 **문제 → 판단 → 결과**가 코드와 주석에 남아 있는 것들입니다.

### 1. 서버 권위 상호작용 — 오브젝트가 네트워크를 모르게 만들기

| 파일 | 내용 |
|---|---|
| [`Obj/IInteractable.cs`](Obj/IInteractable.cs) | 3멤버 계약. 전체 프로젝트에서 26개 클래스가 이걸 구현합니다 |
| [`Obj/Generator/IHoldInteractable.cs`](Obj/Generator/IHoldInteractable.cs) | 길게 누르는 상호작용 계약 |
| [`Obj/InteractionSystem.cs`](Obj/InteractionSystem.cs) | 클라이언트 감지 · 프롬프트 · 홀드 상태 관리 |
| [`Player/NetworkInteraction.cs`](Player/NetworkInteraction.cs) | **서버 검증과 중계가 모인 곳** |

클라이언트는 레이캐스트로 찾은 대상의 `netId`만 보내고, 서버가 스폰 여부 → 거리 → 조건을 재검증한 뒤 실행합니다.
오브젝트는 세 멤버만 구현하면 네트워크를 전혀 모르는 채로 이 경로에 붙습니다.

**볼 만한 지점** — `ServerDistanceTo()`의 주석. 클라이언트 레이캐스트는 콜라이더 *표면*을 맞히는데
서버 검증이 *피벗* 기준이라, 큰 오브젝트에서 화면상 붙어 있어도 상호작용이 조용히 거부되던 문제를
`bounds.ClosestPoint()`로 해결한 기록입니다.

### 2. 라운드 수명주기 — 주기 전송 없는 타이머

| 파일 | 내용 |
|---|---|
| [`Network/Game/RoundManager.cs`](Network/Game/RoundManager.cs) | 페이즈 머신 · 타이머 · 승패 일괄 판정 |
| [`Network/Game/RoundReadyGate.cs`](Network/Game/RoundReadyGate.cs) | 전원 로딩 대기 게이트 (서버 권위) |
| [`UI/Loading/LoadingScreen.cs`](UI/Loading/LoadingScreen.cs) | 씬·네트워크 준비까지 화면을 가리는 로딩 |

종료 시각 `double` 하나만 동기화하고 클라이언트가 `NetworkTime`으로 남은 시간을 계산합니다.
타이머 주기 전송이 0회이고 씬 로딩 시차의 영향도 받지 않습니다.

**볼 만한 지점** — 로딩 화면이 열려 있는 동안 입력 잠금을 함께 소유하게 해서
**"화면이 사라지는 시점 = 입력이 열리는 시점"을 구조적으로 일치**시킨 부분,
그리고 무한 대기를 막는 3중 안전장치(연결 기준 재평가 / 게이트 타임아웃 / 게이트 부재 시 즉시 시작).

### 3. 3단계 전력 — 기존 코드를 고치지 않는 확장

| 파일 | 내용 |
|---|---|
| [`Obj/Light/PowerSystem.cs`](Obj/Light/PowerSystem.cs) | Main / Blackout / Emergency 3단계 서버 권위 관리 |
| [`Obj/Light/PoweredObject.cs`](Obj/Light/PoweredObject.cs) | 기능 스크립트를 건드리지 않고 붙이는 범용 컴포넌트 |

2단계(on/off)에서 3단계로 확장하면서 `IsPowered`의 **의미를 "Main일 때만 true"로 고정**하고,
비상전력이 필요한 대상만 새 프로퍼티를 보게 했습니다. 기존 소비자 수정량 0.

**볼 만한 지점** — `Start()`의 경고 주석(실행 순서 때문에 발전기가 켠 전력을 되돌리던 버그)과
`BlackoutRoutine()`의 코루틴 경합 2중 방어.

### 4. 소리 기반 AI — 인터페이스로 결합 끊기

| 파일 | 내용 |
|---|---|
| [`Obj/NoiseSystem.cs`](Obj/NoiseSystem.cs) | 서버 권위 소리 이벤트 허브 + `INoiseSource` 계약 |
| [`Obj/Monster.cs`](Obj/Monster.cs) | NavMesh 상태 머신 AI (소리 소비자) |

몬스터는 소리를 낸 주체가 무엇인지 알지 못하고 인터페이스로만 판단합니다.
그 덕분에 발소리·총성·문 여닫힘·근접 공격을 차례로 붙이는 동안 **AI 코드는 한 줄도 고치지 않았습니다.**
클라이언트가 가짜 소리를 만들어 몬스터를 유인할 수 없도록 `Emit`은 서버에서만 통과합니다.

### 5. 에디터 도구 — 번역 누락 감사와 일괄 적용

| 파일 | 내용 |
|---|---|
| [`Editor/LocalizationAuditTool.cs`](Editor/LocalizationAuditTool.cs) | 번역 누락 텍스트를 찾아 CSV로 내보내기 |
| [`Editor/LocalizationApplyTool.cs`](Editor/LocalizationApplyTool.cs) | 키를 채운 CSV로 컴포넌트 일괄 부착 |

핵심 난점은 "스크립트가 런타임에 채우는 텍스트"를 문자열 검색으로 구분할 수 없다는 점이었습니다.
씬의 모든 `MonoBehaviour`를 `SerializedObject`로 열어 직렬화 필드를 순회하며 텍스트 컴포넌트를 참조하는
집합을 만들고, 그것을 감사·적용 양쪽에서 동일 기준으로 제외해 해결했습니다.

실측 — 메인 씬 113개 키 추가, 메인 메뉴는 46개 문구 중 26개가, 로비는 69개 중 37개가 기존 키 재사용 가능한 중복이었습니다.

## 공개하지 않은 것

| 제외 | 사유 |
|---|---|
| 나머지 게임플레이 스크립트 | 분량 때문입니다. 위 13개가 설계 판단이 가장 잘 드러나는 것들입니다 |
| **음성 모사 기능 전체** | 프로젝트의 핵심 기술이라 구현을 비공개로 유지합니다. **동작은 플레이 영상으로만 시연**합니다 |
| Unity 프로젝트(씬·프리팹·에셋) | 사용 중인 **유료 에셋은 재배포가 라이선스 위반**입니다 |
| 외부 패키지 (Mirror, TextMesh Pro, URP 등) | 제 작업물이 아닙니다 |

발췌본이라 위 13개 파일도 여기 없는 타입을 참조합니다. 의도된 것이며 그대로 빌드되지 않습니다.

## 개발 방식

이 프로젝트는 **AI 코딩 도구를 적극적으로 활용해 개발했습니다.** 숨길 이유가 없다고 생각해 밝힙니다.

제가 담당한 것은 다음입니다.

- **아키텍처 결정** — 서버 권위 경계를 어디에 둘지, 무엇을 동기화하고 무엇을 로컬 계산으로 넘길지,
  어떤 인터페이스로 결합을 끊을지
- **생성된 코드의 검토와 수정** — 그대로 채택한 코드는 없습니다. 네트워크 권한 누락, 초기화 순서 가정,
  코루틴 경합, 클라/서버 판정 불일치는 반복적으로 나타나 매번 직접 확인해야 했습니다
- **통합과 회귀 대응** — 실제 멀티플레이 환경에서 검증하고, 재현되지 않는 문제는 진단 로그를 심어 원인을 좁혔습니다
- **판단** — 동작하지만 구조를 나쁘게 만드는 변경은 되돌렸습니다

주석에 "무엇을 하는가"보다 **"왜 이렇게 했는가", "이렇게 하면 왜 깨지는가"** 가 많은 것은 그 과정의 흔적입니다.
대부분 실제로 한 번 깨진 뒤 남긴 기록입니다.
