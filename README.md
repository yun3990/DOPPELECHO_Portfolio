# DOPPELECHO — 핵심 코드 포트폴리오

Unity + [Mirror](https://github.com/MirrorNetworking/Mirror) 기반 비대칭 멀티플레이어 1인칭 협동·추리 게임입니다.
정거장에 고립된 승무원들이 탈출 미션을 수행하는 동안, 정체를 숨긴 임포스터가 이를 방해합니다.

> 이 저장소는 전체 프로젝트가 아니라 핵심 스크립트 13개를 발췌한 것입니다.
> 다른 파일에 대한 참조가 남아 있어 그대로 컴파일되지 않으며, 열람용으로 구성했습니다.

## 공개한 코드

다섯 개 주제로 나누어 정리했습니다. 각 주제는 문제 상황과 판단 근거가 코드와 주석에 남아 있는 것들입니다.

### 1. 서버 권위 상호작용 — 오브젝트가 네트워크를 모르게 만들기

| 파일 | 내용 |
|---|---|
| [`Obj/IInteractable.cs`](Obj/IInteractable.cs) | 3멤버 계약. 전체 프로젝트에서 26개 클래스가 구현합니다 |
| [`Obj/Generator/IHoldInteractable.cs`](Obj/Generator/IHoldInteractable.cs) | 길게 누르는 상호작용 계약 |
| [`Obj/InteractionSystem.cs`](Obj/InteractionSystem.cs) | 클라이언트 감지 · 프롬프트 · 홀드 상태 관리 |
| [`Player/NetworkInteraction.cs`](Player/NetworkInteraction.cs) | 서버 검증과 중계 |

클라이언트는 레이캐스트로 찾은 대상의 `netId`만 보내고, 서버가 스폰 여부 → 거리 → 조건을 재검증한 뒤 실행합니다.
오브젝트는 세 멤버만 구현하면 네트워크를 알지 못한 채 이 경로에 연결됩니다.

**구현 과정에서 해결한 문제** — 클라이언트 레이캐스트는 콜라이더 표면을 맞히는데 서버 검증은 피벗 기준이어서,
큰 오브젝트에서는 화면상 접촉한 상태에서도 상호작용이 거부되었습니다.
`ServerDistanceTo()`에서 `bounds.ClosestPoint()` 기준으로 변경해 두 판정을 일치시켰습니다.

### 2. 라운드 수명주기 — 주기 전송 없는 타이머

| 파일 | 내용 |
|---|---|
| [`Network/Game/RoundManager.cs`](Network/Game/RoundManager.cs) | 페이즈 머신 · 타이머 · 승패 일괄 판정 |
| [`Network/Game/RoundReadyGate.cs`](Network/Game/RoundReadyGate.cs) | 전원 로딩 대기 게이트 (서버 권위) |
| [`UI/Loading/LoadingScreen.cs`](UI/Loading/LoadingScreen.cs) | 씬·네트워크 준비까지 화면을 가리는 로딩 |

종료 시각 `double` 하나만 동기화하고 클라이언트가 `NetworkTime`으로 남은 시간을 계산합니다.
타이머의 주기적 전송이 없고 씬 로딩 시차의 영향도 받지 않습니다.

**기술적 판단** — 로딩 화면이 열려 있는 동안 입력 잠금을 함께 소유하도록 해서,
화면이 닫히는 시점과 입력이 열리는 시점을 구조적으로 일치시켰습니다.
대기가 끝나지 않는 경우에 대비해 세 가지 안전장치를 두었습니다(연결 기준 재평가 / 게이트 타임아웃 / 게이트 부재 시 즉시 시작).

### 3. 3단계 전력 — 기존 코드를 고치지 않는 확장

| 파일 | 내용 |
|---|---|
| [`Obj/Light/PowerSystem.cs`](Obj/Light/PowerSystem.cs) | Main / Blackout / Emergency 3단계 서버 권위 관리 |
| [`Obj/Light/PoweredObject.cs`](Obj/Light/PoweredObject.cs) | 기능 스크립트를 수정하지 않고 부착하는 범용 컴포넌트 |

2단계(on/off)에서 3단계로 확장하면서 `IsPowered`의 의미를 "Main일 때만 true"로 고정하고,
비상전력이 필요한 대상만 별도 프로퍼티를 참조하도록 했습니다. 기존 소비자 코드는 수정하지 않았습니다.

**핵심 문제 해결** — `PowerSystem.Start()`가 `GeneratorController.OnStartServer()`보다 늦게 실행되어
발전기가 켠 전력을 되돌리는 문제가 있었습니다. 초기화에서 현재 상태를 그대로 반영하도록 변경했고,
암전 대기 코루틴은 취소와 상태 재검증 두 단계로 경합을 방어했습니다.

### 4. 소리 기반 몬스터 AI — 인터페이스로 결합 분리

| 파일 | 내용 |
|---|---|
| [`Obj/NoiseSystem.cs`](Obj/NoiseSystem.cs) | 서버 권위 소리 이벤트 허브 + `INoiseSource` 계약 |
| [`Obj/Monster.cs`](Obj/Monster.cs) | NavMesh 상태 머신 (소리 소비자) |

몬스터는 소리를 낸 주체가 무엇인지 알지 못하고 인터페이스로만 판단합니다.
그 덕분에 발소리·총성·문 여닫힘·근접 공격을 차례로 추가하는 동안 몬스터 쪽 코드는 수정하지 않았습니다.
클라이언트가 소리를 만들어 몬스터를 유인할 수 없도록 `Emit`은 서버에서만 통과합니다.

### 5. 에디터 도구 — 번역 누락 감사와 일괄 적용

| 파일 | 내용 |
|---|---|
| [`Editor/LocalizationAuditTool.cs`](Editor/LocalizationAuditTool.cs) | 번역 누락 텍스트를 찾아 CSV로 내보내기 |
| [`Editor/LocalizationApplyTool.cs`](Editor/LocalizationApplyTool.cs) | 키를 채운 CSV로 컴포넌트 일괄 부착 |

**주요 구현 사항** — 화면에 표시되는 텍스트 중 스크립트가 런타임에 채우는 것은 문자열 검색으로 구분할 수 없어,
그대로 두면 대부분이 오탐으로 분류되었습니다. 씬의 모든 `MonoBehaviour`를 `SerializedObject`로 열어
직렬화 필드를 순회하며 텍스트 컴포넌트를 참조하는 집합을 만들고, 이를 감사와 적용 양쪽에서 동일한 기준으로 제외했습니다.

적용 결과 메인 씬에 113개 키를 추가했고, 메인 메뉴는 46개 문구 중 26개, 로비는 69개 중 37개가
기존 키로 대체 가능한 중복이었습니다.

## 공개하지 않은 것

| 제외 | 사유 |
|---|---|
| 나머지 게임플레이 스크립트 | 분량 관계로 설계 판단이 드러나는 13개만 선별했습니다 |
| 음성 모사 기능 전체 | 프로젝트의 핵심 기술이라 구현을 비공개로 유지하며, 동작은 영상으로만 시연합니다 (개발 과정은 [아래](#ai-음성-변환-기술-개발-과정) 참고) |
| Unity 프로젝트(씬·프리팹·에셋) | 사용 중인 유료 에셋은 재배포가 라이선스 위반입니다 |
| 외부 패키지 (Mirror, TextMesh Pro, URP 등) | 직접 작성한 코드가 아닙니다 |

발췌본이므로 위 13개 파일도 이 저장소에 없는 타입을 참조합니다. 의도한 구성이며 그대로 빌드되지 않습니다.

## 개발 방식

이 프로젝트는 AI 코딩 도구를 활용해 개발했습니다.

- **아키텍처 결정** — 서버 권위 경계 설정, 동기화 대상과 로컬 계산의 구분,
  인터페이스를 통한 결합 분리
- **생성 코드의 검토와 통합** — AI가 생성한 코드는 실제 멀티플레이 환경에서 검토·수정·통합했으며,
  네트워크 권한, 초기화 순서, 코루틴 경합, 클라이언트·서버 판정 불일치를 직접 검증했습니다
- **회귀 대응** — 재현되지 않는 문제는 진단 로그를 추가해 원인을 좁혔습니다
- **설계 판단** — 동작하더라도 구조를 해치는 변경은 되돌렸습니다

주석에 "왜 이렇게 했는가", "이렇게 하면 어떤 문제가 생기는가"가 많은 것은 이 과정에서 남은 기록입니다.
